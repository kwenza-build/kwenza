== At a glance

[source,toml]
----
# kwenza.toml
[package]
name = "hello-world"
group = "com.example"
version = "0.1.0"
java-version = "21"
main-class = "com.example.Main"

[dependencies]
guava = { module = "com.google.guava:guava", version = "33.2.1-jre" }
----

[source,console]
----
$ kwenza run
resolve: using locked dependencies (kwenza.lock)
compile: target/classes
run: java -cp target/classes (+7 dependency jars) com.example.Main
Hello from Kwenza: kwenza builds java
----

* *Declarative.* The manifest is data. It never runs, so reading it tells you everything.
* *Interoperable.* Real Maven Central dependencies, your existing `~/.m2` cache, standard
  `src/main/java`. Your IDE and tools keep working.
* *Reproducible.* `kwenza.lock` wins by default: no network unless your dependencies changed.
* *Transparent.* Every command prints what it actually ran.

NOTE: "kwenza" is isiXhosa for "to make."

== Install

kwenza needs JDK 21 or newer. Until the first release is packaged, build it from source:

[source,bash]
----
git clone https://github.com/kwenza-build/kwenza.git && cd kwenza
./bootstrap.sh && bin/kwenza package
export PATH="$PWD/bin:$PATH"
----

Then, in any directory with a `kwenza.toml`:

[source,bash]
----
kwenza build      # resolve dependencies + compile
kwenza test       # run src/test/java via the JUnit Platform
kwenza run        # build + execute [package].main-class
kwenza package    # build + produce a runnable thin jar
kwenza help run   # the manual page for any command
----

See link:docs/modules/ROOT/pages/getting-started.adoc[Getting started] for the full walkthrough,
including a new project from scratch.

== Status

kwenza covers the full inner loop for a single-module Java project: resolve, compile, test, run,
package, with a lockfile. Multi-module workspaces, `--fat` jars, a `[scripts]` runner and an
`--offline` mode are deliberately deferred; see link:ROADMAP.adoc[the roadmap].

== Contributing

kwenza builds itself, so `bin/kwenza package && bin/kwenza test` is the whole dev loop.
link:AGENTS.md[AGENTS.md] explains the design decisions and conventions (Conventional Commits,
TDD, changelog entries) for contributors, human or AI.
